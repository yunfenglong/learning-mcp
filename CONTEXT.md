# Domain context

Learning MCP Suite is a cloud MCP service for OAuth-capable MCP clients. It runs entirely on Cloudflare: one public suite Worker and one private broker Worker. pnpm owns its package and lockfile.

A **suite user** is identified by a verified identity anchor. Provider sign-in uses the provider type, configured HTTPS origin and stable authenticated user ID; the first provider adapter supports Okta. Ed sign-in uses the verified Ed user ID. Platform-based sign-in has been removed. Existing platform-anchored records remain isolated; provider sign-in creates a separate account and does not merge identities. OAuth grants, notice acceptance, credentials, platform sessions and course mappings are isolated from other users. The private broker can reuse that user's saved SSO across configured platforms. No independent OIDC application is required; future sign-ins must use the same identity anchor.

A **platform connection** is a verified Ed, Moodle or OnTrack account. The broker may reuse one user's SSO cookies between the configured Moodle and OnTrack origins. With explicit password retention consent and a separate additional TOTP retention choice, it also keeps the user's encrypted password and optional TOTP configuration for automatic reauthentication. A one-time MFA code is transient. Interactive provider sign-in discovers MFA choices from the current provider page and keeps one volatile, browser-bound transaction in the private broker for up to five minutes. It submits each code once, stops after three validation or verification errors. Only a verified active provider session establishes the suite identity. TOTP does not satisfy Push, Passkey, device checks or provider policy changes.

A **course association** maps a user-selected code, location, year, teaching period and timezone to any subset of platform IDs from fresh enrollment discovery, including just Moodle. Codes and campuses are generic strings. Differences in platform labels or semester/location metadata are review warnings, not restrictions on manual associations. Composite slash labels remain intact; shared components only suggest candidates. Optional Ed institutional filters use raw metadata; title or semester matches never establish institutional identity.

A **binding preview** is an account-bound, encrypted plan for one or more course associations. It shows platform identifiers, label differences and changes to existing mappings without editing them. One user confirmation commits the whole batch atomically; stale discovery or registry changes invalidate the plan. A mapping code is a user-confirmed label, not a platform's display identifier. Matching suggestions require confirmation rather than automatically linking courses with similar codes.

A **usage acceptance** records the current notice version, terms version and timestamp after authenticated browser confirmation. The notice explains cloud credential processing, client data transfer and required account/content permissions. Notice acknowledgement and terms acceptance are separate required browser choices; password and additional TOTP retention are optional default-off choices. The private broker records opted-in retention choices and time. Public privacy, terms and data-control pages describe each self-hosted instance; `LEGAL_CONFIG` supplies escaped public operator/contact disclosures. The repository maintainer is not automatically another instance’s operator. Access-removal controls remain available before accepting an updated notice. It does not grant rights or certify compliance. Attendance discovery returns candidates with evidence and partial coverage, never a submission.

**Platform renewal** is separate from the MCP client’s OAuth refresh. Moodle uses a scoped cookie jar and a session-bound CSRF `sesskey`; OnTrack uses an expiring access token and private refresh cookies. The broker attempts HTTP renewal first, verifies the same platform identity, persists cookie rotation and serializes per-user operations. A rejected session can require browser SSO; a transient upstream failure triggers backoff. Forgetting SSO credentials retains platform sessions and their renewal material; disconnect removes that platform’s session and renewal material.

A **platform base link** is the exact public HTTPS origin supplied by the user on first Connect. The broker saves it per account and uses it for reads, sign-in and renewal. A different base link requires disconnecting and connecting that platform again. Moodle and OnTrack addresses have no deployment default and are not Worker configuration.
